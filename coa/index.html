💡 Attachment 5: Solutions — COA, Step by Step

Every solution below is written out in full, in the same order as the ranked topics above. Nothing is hidden behind a tap — read straight down, and copy the steps into your answer in the same order. Diagrams are described block by block, so you can draw them exactly as written.

Solution: 8086 architecture (8 marks, Q5a both papers)

What to write first: 8086 is a 16-bit microprocessor, 20-bit address bus (1 MB memory), 16-bit data bus, 40 pins, 5–10 MHz. It has two parts that work in parallel: the Bus Interface Unit (BIU) fetches, the Execution Unit (EU) executes.

Diagram to draw: Two big boxes, BIU on top, EU below. BIU contains: segment registers (CS, DS, SS, ES), Instruction Pointer (IP), address adder, 6-byte instruction queue. EU contains: ALU, flags register, general registers (AX, BX, CX, DX), pointer/index registers (SP, BP, SI, DI), control unit. Arrow from queue to EU labelled “instruction stream”, arrow from BIU to memory labelled “20-bit physical address”.

Steps in words: 1) BIU calculates physical address = segment × 16 + offset. 2) It fetches bytes ahead into the 6-byte queue while EU is busy — this is pipelining, so fetch and execute overlap. 3) EU takes the instruction from the queue, decodes it, does the ALU operation, updates flags (Carry, Zero, Sign, Overflow, Parity, Auxiliary). 4) Result goes back through BIU to memory or a register. End with one line: because fetch and execute overlap, 8086 is faster than a processor that fetches, then executes, then fetches again.

Solution: Cache mapping (8 marks)

Given (Dec Q3a): Main memory 64 MB, cache 32 KB, line/block 8 bytes.

Step 1 — bits: 64 MB = 226 bytes, so the memory address is 26 bits. 8 bytes = 23, so the word/offset field is 3 bits. Cache lines = 32 KB ÷ 8 = 4,096 lines = 212.

Step 2 — Direct mapping: Address = Tag 11 bits | Line (index) 12 bits | Offset 3 bits. 11 + 12 + 3 = 26. One fixed line per block. Fast and simple, but two blocks that map to the same line keep throwing each other out — this is conflict misses.

Step 3 — Associative mapping: No index at all. Address = Tag 23 bits | Offset 3 bits. 23 + 3 = 26. Any block can go in any line, so no conflict misses, but every line must be searched in parallel — expensive hardware.

Step 4 — Set associative (May Q4a, compare all three): Lines are grouped into sets. If it is k-way, sets = 4,096 ÷ k, index = log2(sets), tag = 26 − index − 3. It is the middle path: fewer conflicts than direct, cheaper than fully associative. Write this comparison as a 3-row table in the exam: direct = fixed place, fast, most conflicts; associative = any place, slowest/expensive, no conflicts; set associative = set fixed, place inside set free, balanced.

Solution: Non-restoring division (8 marks)

Algorithm, in order: Registers: A (remainder, starts 0), Q (dividend), M (divisor), count n = number of bits in Q. Repeat n times: 1) Shift left A:Q together by one. 2) If A is positive, A = A − M; if A is negative, A = A + M. 3) If the new A is positive, set Q0 = 1; if negative, set Q0 = 0. After n steps, if A is negative, do one final restore: A = A + M. Q is the quotient, A is the remainder. Key difference from restoring division: you do not restore A in the middle of the loop — you only fix it once at the end, so it is faster.

Flowchart to draw: Start → A=0, count=n → Shift left A:Q → Is A ≥ 0? Yes → A=A−M, No → A=A+M → Is new A ≥ 0? Yes → Q0=1, No → Q0=0 → count = count − 1 → count = 0? No → loop back, Yes → Is A < 0? Yes → A=A+M → Stop with Q, A.

Worked example 1 — Dec: 13 ÷ 3. 13 = 1101, 3 = 0011, n = 4. Running the steps above gives Q = 0100 = 4, A = 0001 = 1. Check: 3 × 4 + 1 = 13. Correct.

Worked example 2 — May: 15 ÷ 2. 15 = 1111, 2 = 0010, n = 4. Running the same steps gives Q = 0111 = 7, A = 0001 = 1. Check: 2 × 7 + 1 = 15. Correct.

Solution: Microprogrammed control unit (8 marks, Dec Q4a)

Diagram to draw: Boxes in a row: Control Memory (ROM, holds microinstructions) → Control Register → Decoder → Control signals to ALU, registers and memory. Below them: Sequencer / Next-address generator, fed by the opcode, flags and the current microinstruction. A microinstruction is wider than a normal instruction: each bit (or field) is one control signal.

Steps: 1) Fetch the machine instruction, take its opcode. 2) The sequencer uses the opcode to find the first microinstruction for that instruction in control memory. 3) Each microinstruction is read out, decoded, and its control signals switch on the right datapath parts for one micro-step. 4) The next-address field (plus flags/conditions) picks the next microinstruction, until the last one ends the machine instruction and the next fetch starts.

Why it is used: Complex instructions become a program in control memory instead of a maze of gates, so changing an instruction means changing ROM, not rewiring hardware. Price: it is slower than hardwired control, because every step goes through control memory.

Solution: Booth's algorithm (7 marks, Q5b both papers)

Algorithm, in order: Registers: A (starts 0), Q (multiplier), Q−1 (starts 0), M (multiplicand), count = number of bits. Repeat count times: look at the pair Q0, Q−1. If it is 10, A = A − M. If it is 01, A = A + M. If it is 00 or 11, do nothing. Then arithmetic-shift right the whole A:Q:Q−1 together (sign bit of A copies into the top). At the end, A:Q together is the product.

Worked example — Dec: (12) × (−5) = −60. Set M = −5 = 11011, Q = 12 = 01100, A = 00000, Q−1 = 0, 5 steps. Step 1: 00, no op → A=00000, Q=00110, Q−1=0. Step 2: 00, no op → A=00000, Q=00011, Q−1=0. Step 3: 10, A = A − M = 5 → shift → A=00010, Q=10001, Q−1=1. Step 4: 11, no op → A=00001, Q=01000, Q−1=1. Step 5: 01, A = A + M = −4 → shift → A=11110, Q=00100. Final A:Q = 1111000100 = −60. Correct.

Worked example — May: (−8) × (−3) = 24. Set M = −3 = 1101, Q = −8 = 1000, A = 0000, Q−1 = 0, 4 steps. Steps 1–3: 00, no op each time → A=0000, Q=0001, Q−1=0. Step 4: 10, A = A − M = 3 → shift → A=0001, Q=1000. Final A:Q = 00011000 = 24. Correct. Note: you may swap which number is M and which is Q — the product is the same, but write down which one you chose before you start.

Solution: Pipeline hazards (7 marks)

Definition first: A hazard is a situation where the next instruction in the pipeline cannot run in its slot without giving a wrong result, so the pipeline must stall or forward data.

1) Structural hazard: Two instructions need the same hardware at the same time (for example, one memory for both instruction fetch and data access). Fix: split memories (Harvard style), duplicate hardware, or stall.

2) Data hazard: An instruction needs a result the previous instruction has not finished yet. Types: RAW (read after write — the real problem), WAR (write after read), WAW (write after write). Fixes: forwarding/bypassing (send the ALU result straight to the next instruction, no wait for write-back), stalling with a bubble, and compiler reordering of independent instructions.

3) Control hazard: A branch changes the flow, so the instructions already fetched after it may be wrong. Fixes: stall until the branch is resolved, branch prediction (guess taken/not taken), delayed branch (fill the slot with a useful instruction), and speculative execution with flush on a wrong guess.

End with: hazards do not make pipelining useless — they cost a few cycles, but a pipelined processor still finishes far more instructions per cycle than a non-pipelined one.

Solution: Flynn's classification (5 marks Dec, 8 marks May)

SISD — Single Instruction, Single Data: One instruction stream, one data stream. The classic single processor: one instruction at a time, on one piece of data. Example: a simple uniprocessor.

SIMD — Single Instruction, Multiple Data: One instruction, applied to many data items at once. Example: vector processors, GPU-style array processing, multimedia instructions.

MISD — Multiple Instruction, Single Data: Many instructions, one data stream. Rare in practice; textbook example is fault-tolerant systems where several processors run different checks on the same data and compare results.

MIMD — Multiple Instruction, Multiple Data: Many processors, each with its own instruction and data. Example: multicore processors, multiprocessor systems, clusters. This is the normal form of modern parallel computers.

Memory trick for the exam: the first letter is instructions, the second is data. Write the 2 × 2 grid first, then one example per box.

Solution: Memory hierarchy / characteristics (7 marks Dec, 5 marks May)

Diagram to draw (top to bottom): Registers (fastest, smallest, most expensive per bit) → Cache (L1, L2) → Main memory (RAM) → Secondary storage (SSD/HDD) → Tertiary (tape/optical, slowest, largest, cheapest). Draw it as a pyramid, wide at the bottom.

Characteristics, in order: 1) Capacity — increases going down the pyramid. 2) Access time — increases going down (registers ~1 cycle, cache ~10 cycles, RAM ~100 cycles, disk ~millions). 3) Cost per bit — decreases going down. 4) Volatility — registers, cache and RAM lose data without power; disk/tape keep it. 5) Access method — registers/cache by address, disk by block/sector.

Why the hierarchy exists: No single memory is fast, large and cheap at once, so the system keeps the data you are using now at the top, and the rest below, and moves data up on demand. That is the whole point — write it as your closing line.

Solution: Number conversion (5 marks, Q1 both papers)

Rule for the exam: A calculator with a number-conversion function is NOT allowed, so show every step by hand. Integer part: divide by the base, keep remainders, read bottom to top. Fraction part: multiply by the base, keep integer parts, read top to bottom.

Dec — (345.35)10: Integer 345 = 1010110012 = 5318 = 15916. Fraction .35 ≈ .010112 ≈ .26318 ≈ .599916 (approximate — fractions repeat, so write “≈” and stop after 4–5 digits). Full answers: 101011001.010112, 531.26318, 159.599916.

Dec — (818.55)10: Integer 818 = 11001100102 = 14628 = 33216. Fraction .55 ≈ .100012 ≈ .43148 ≈ .8CCC16. Full answers: 1100110010.100012, 1462.43148, 332.8CCC16.

May — to hexadecimal + addition: (74.25)10 = 4A.416 (74 = 4A, .25 = .4). (47.50)10 = 2F.816 (47 = 2F, .50 = .8). Addition in hex: 4A.4 + 2F.8 = 79.C16. Check in decimal: 74.25 + 47.50 = 121.75, and 79.C16 = 121.75. Correct.

Solution: Associative memory (5 marks, Q1 both papers)

Definition: Associative memory (content-addressable memory, CAM) is searched by content, not by address. You give it a piece of data (or a key), and it returns the location(s) where that data lives — all locations are checked in parallel.

How it works: Each memory word has a match circuit. The search key is broadcast to all words at once, every word compares itself to the key, and the matching word(s) raise a match line. No address calculation, no sequential scan.

Usages to list: 1) Cache tag lookup — checking whether a block is already in cache. 2) Translation lookaside buffer (TLB) — virtual-to-physical address translation. 3) Routing tables in network switches/routers — finding the output port for a destination address at wire speed. 4) Pattern matching, databases and AI lookup tables where search by value is the whole job.

Trade-off to end with: Much faster for search than normal RAM, but far more expensive per bit because of the match logic in every cell — so it is used in small, critical places (cache, TLB, routers), never as main memory.

Solution: IEEE 754 floating point (8 marks, May Q2a)

Convert (56.45)10 to single precision (32 bits).

Step 1 — binary: 56 = 1110002. .45 ≈ .0111001100112. So 56.45 ≈ 111000.0111001100112.

Step 2 — normalise: Move the binary point to after the first 1: 1.110000111001100110011 × 25. The exponent before bias is 5.

Step 3 — fields: Sign = 0 (positive). Biased exponent = 127 + 5 = 132 = 100001002 (8 bits). Mantissa = the 23 bits after the leading 1: 11000011100110011001101 (the leading 1 is hidden, not stored).

Step 4 — full 32-bit answer: 0 | 10000100 | 11000011100110011001101. Grouped: 0100 0010 0110 0001 1100 1100 1100 1101. Write the sign, exponent and mantissa on separate lines first, then the combined 32 bits — examiners give marks for the fields even if one bit slips.

Solution: 80386DX operation modes (7 marks, May Q6b)

1) Real mode (real-address mode): The 80386 starts here, exactly like an 8086. 20-bit addressing, 1 MB memory, no protection, no paging, one program at a time in effect. Used for booting and for old DOS programs.

2) Protected mode: The full 32-bit mode. 4 GB address space, segmentation + paging, privilege levels (rings 0–3), memory protection so one program cannot corrupt another, and multitasking. This is the normal mode for modern operating systems.

3) Virtual 8086 mode: A mode inside protected mode. It creates a virtual 8086 machine for an old program, so several DOS programs can run at once, each thinking it owns a 1 MB 8086, while the OS in protected mode keeps them separate and safe.

Exam line to finish: real = 8086-compatible, protected = full 32-bit + protection, virtual 8086 = 8086 programs running safely inside protected mode.

Solution: Bus arbitration (5 marks, Dec Q6a)

Problem first: Several devices want the bus at the same time. Arbitration decides who gets it, in what order, so transfers do not collide.

1) Daisy chain (serial): A grant signal passes from device to device in a fixed chain. The device nearest the arbiter wins. Simple, cheap, but unfair to devices at the end of the chain, and one broken link breaks the chain.

2) Polling (centralised, counted): The arbiter polls each device in turn and grants the bus to the first requesting device it finds. Fairer than daisy chain, but polling takes time.

3) Independent request (parallel): Every device has its own request and grant lines to the arbiter. The arbiter picks by priority (fixed or rotating). Fastest and fairest, but needs the most lines and hardware.

Decentralised note: In decentralised arbitration there is no single arbiter — devices negotiate among themselves using priority codes on the bus. End with: centralised = one arbiter, decentralised = devices decide together.

Solution: Addressing modes of 8086 (5 marks, Dec Q1b)

Give one example for each mode, in this order:

Immediate: Data is in the instruction itself. Example: MOV AX, 1234H — 1234H goes straight into AX.

Register: Data is in a register. Example: MOV AX, BX — copy BX into AX.

Direct: Address is in the instruction. Example: MOV AX, [1234H] — load from memory location 1234H.

Register indirect: Address is in a register. Example: MOV AX, [BX] — load from the address held in BX.

Based / indexed: Address = base register + displacement, or index register + displacement. Example: MOV AX, [BX+10H] and MOV AX, [SI+10H].

Based-indexed: Address = base + index + displacement. Example: MOV AX, [BX+SI+10H] — used for arrays and tables.

Implied / inherent: No operand written, the instruction implies it. Example: CLC (clear carry flag), STC, NOP.

Solution: Instruction pipeline (5 marks, May Q1b)

Stages, in order: 1) Fetch — get the instruction from memory using PC. 2) Decode — work out what it is and read its operands. 3) Execute — ALU does the operation or calculates an address. 4) Memory access — read/write data memory if the instruction needs it. 5) Write-back — store the result into a register.

Why it helps: While one instruction is executing, the next is being decoded and the one after that is being fetched — like an assembly line. In the ideal case one instruction finishes every cycle, even though each single instruction still takes 5 cycles.

What breaks it: Hazards (see Pipeline hazards above) — data dependencies, structural conflicts and branches all cause stalls or flushes, so real throughput is below the ideal one-per-cycle. That link is worth one mark: mention hazards by name at the end.

How to pass — for exam tension

Minimum study · target 30+ / 60

Breathe. You do not need all 6 modules, and you do not need 60 out of 60. Passing lives around 27–30 marks out of 60. The plan below puts 30 marks on the table from just Q1 plus the fixed Q5 — so even with mistakes, you stay above the pass band. Add the safe set and it becomes 45 marks on the table.

Step 1 — the minimum set (learn these first, in this order)

LearnWhere it paysMarks on the table

Step 2 — the safe set (add this and you cover 45 marks)

One more full question — cache mapping or non-restoring division (15) = 15 more marks. 30 + 15 = 45 out of 60, the distinction line.

Step 3 — how to attempt in the hall (2 hours)

Q1 (25 min) → Q5 (30) → strongest of Q3/Q4 (30) → check (15). Draw the 8086 diagram and the cache-mapping format once, neatly — they carry marks by themselves.

Honest note, not a guarantee. Pattern from only 2 papers, and COA rotates slots, so learn the topic, not the slot. It raises your odds; it is not a guarantee.
